1. Ficha del Ejercicio 37

App: MI PORTAFOLIO · Categoría: Proyecto de vida

Problema: Al postular a la universidad no hay dónde mostrar lo que uno ya hizo.

Usuario: El propio estudiante (Diego Fernando Zúñiga Aguilar).

Las tres funciones mínimas (P0 + M1):

  1. Registrar proyecto con descripción, imagen y enlace.
  2. Sección «sobre mí» con habilidades.
  3. Formulario o datos de contacto.

Dato clave que maneja (M2): Proyectos propios con su enlace (persistencia en localStorage).

Sello de IA (M5): La IA convierte las notas sueltas del estudiante en una descripción profesional de cada proyecto, y el estudiante la corrige para que no diga nada falso.

Dónde guardar: Proyectos publicados en el sitio.

2. README.md (Las 13 Partes Completas)

# MI PORTAFOLIO · DIEGO ZÚÑIGA

Plataforma web interactiva para que estudiantes de bachillerato técnico registren, organicen y exhiban sus proyectos de desarrollo de software con rigor profesional al postular a la universidad y al campo laboral.

1. Probala ahora: https://ais-pre-5aga45xqbfsvnxxfuedj2o-757988679085.us-east1.run.app · Repositorio GitHub · Código QR integrado en app · Usuario sin registro obligatorio.

2. Capturas: evidencias/E3-celular.png (Inicio celular), evidencias/E1-despues.png (En uso), evidencias/E5-app.png (Con IA trabajando).

3. Qué hace: Registro y gestión de proyectos, sección sobre mí con habilidades técnicas en 5 áreas, y formulario de contacto con bandeja local y enlaces directos a WhatsApp y correo.

4. Cómo correrlo: git clone ... && npm install && npm run dev (puerto 3000 con backend Express).

5. Tecnologías: TypeScript 5.8+, React 19, Tailwind CSS v4, Node.js + Express 4.x, LocalStorage con respaldo JSON, @google/genai con gemini-3.8-flash (responseSchema) y Plan B heurístico local.

4. Guion de Defensa de 90 Segundos

0:00 – 0:25 (Problema): «Buenos días profesor Javier y compañeros. Mi app es MI PORTAFOLIO, ejercicio 37. Resuelve un problema real que enfrentamos en tercer año: cuando postulamos a la universidad para Ingeniería en Sistemas o a pasantías laborales, no tenemos un lugar propio donde demostrar lo que ya programamos en el INDEL.»

0:25 – 0:55 (Mejora más costosa): «La mejora que más me costó fue M4 combinada con M5. Al principio la IA generaba código que fallaba con URLs locales o dejaba la pantalla en blanco si la API tardaba. Creé un validador nativo con new URL() y un Plan B heurístico en Express para que la app funcione siempre, incluso sin internet en el laboratorio.»

0:55 – 1:30 (Corrección de la IA y móvil): «De lo que la IA me dio, corregí las importaciones viejas, cambié los botones pequeños por áreas táctiles de 44 píxeles para usarla con una mano al sol como probé con Kevin y la profe Ramos, y aseguré que la IA nunca invente datos falsos: el estudiante siempre revisa y corrige la redacción antes de guardar. Muchas gracias.»
